## Scope for Claude

Keep Python/FastAPI, React and Cloudflare Workers AI on the established Free account. Model selection inside this provider is part of the agreed candidate evaluation, not a new provider or paid infrastructure decision. Evaluate alternatives without another architecture approval. No paid upgrade, new provider, repository publication or deployment in this checkpoint. Use Opus subscription as before.

1. Fix observability: distinguish started model calls from completed calls. A timeout currently reports modelCalls=0 despite an actual invocation. Count before dispatch; preserve separate completions and usage-known status. Never imply missing usage is zero billed consumption. Add timeout/provider-failure tests; keep logs free of contents/secrets.

2. Revise the generic extraction instructions to preserve ALL distinct amounts and dated events, including annexes, gross vs net, periodicity, historical/rejected status, and legal organization names. Explicitly require copying stated qualifiers into context and including main date among dated events when supported. Keep summary concise (3 sentences is acceptable), but never gain speed by removing required facts, shortening input silently, weakening schema or hardcoding the test contract. Extend the evaluator with independent atomic checks for missing gross amount, invoice/payment/signing dates, net/period qualifiers and legal forms. Treat 20/24 as the old limited rubric, not 83% general accuracy. Store reusable synthetic regression inputs/evaluation code in the repo; sensitive/full source payloads stay ignored.

3. Bounded comparison: use at most SIX actual provider calls including correction retries (not six HTTP analyses). Check remaining free allowance first and stop on quota/error that would require billing. First compare the revised prompt on current 70B and ONE smaller Cloudflare text-generation model with sufficient context and confirmed json_schema support. Candidate: @cf/meta/llama-3.1-8b-instruct; verify current catalog availability, context and price BEFORE calling. Official JSON Mode docs list it, but its model URL returned 404 during review: do not assume availability or support of a similarly named fast/fp8 variant. Select a documented compatible alternative if necessary and record the reason. Never assume a smaller model is faster or sufficiently accurate. Compare using identical source input, schema and prompt. Use the remaining calls to repeat a promising candidate and test a second synthetic document with different amounts/dates (prevent fixture overfitting). Do not use a response cache to pass timing checks.

4. Replace the per-attempt-only timeout with a bounded overall request deadline. Proposed safety limits: 55 seconds total AI budget, maximum 40 seconds per attempt, client timeout 65 seconds. They are failure ceilings, NOT evidence of meeting <30 seconds. One corrective retry for invalid output uses remaining overall budget; no third call and no automatic retries on provider timeout/quota. If insufficient time remains, return an explicit timeout. Unit-test elapsed budget with controlled time (no slow sleeps). If the chosen model supports tighter limits reliably, document and align defaults, wrangler vars, env examples, frontend timeout and tests.

5. Choose a new default only on measured quality AND latency. Missing mandatory facts/qualifiers, injection obedience or fabricated totals disqualify an apparently faster result. If no candidate meets both, report that honestly and preserve comparison evidence; next architectural option is page-based chunk/extract + deterministic merge with one document-level summary, which also addresses F08, but do not add it blindly in this small experiment.

6. Run backend lint/format/tests and frontend lint/typecheck/tests/build if touched. Record exact model IDs, prompt version, started/completed calls, known tokens, failures, end-to-end and server timing, per-case quality and remaining release gates in docs/LIVE_AI_RESULTS.md and docs/STATUS.md. Update AI_LOG.md. Use logical Conventional Commits and return a concise report.
